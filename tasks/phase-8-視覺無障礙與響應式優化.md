# Phase 8：視覺、無障礙與響應式優化

> 前置：Phase 6 的新版浮動面板與 Phase 7 的系統檢查 UI 已存在  
> 目標：讓浮動面板符合 WCAG 2.2 AA 的核心操作要求，補齊 dialog 與焦點行為，重整首頁資訊架構，並確保 320px 手機、亮色／透明主題及鍵盤／讀屏環境下皆可清楚操作

## 現況問題與決策

| 現況 | 風險／問題 | 決策 |
|---|---|---|
| 浮動面板沒有 dialog ARIA 語意 | 讀屏無法辨識為對話框，也不知道標題 | 僅浮動模式加入 `role="dialog"`、`aria-modal` 與標題關聯 |
| 開啟／關閉未管理焦點，也沒有 Escape 與焦點圈限 | 鍵盤焦點可能落到面板後方，關閉後失去操作位置 | 記錄 opener、初始聚焦、Tab trap、Escape 關閉、關閉後還原焦點 |
| `showScreen()` 雖嘗試聚焦 `h2`，但首頁沒有可聚焦標題，畫面語意也未關聯 | 部分換頁不會被讀屏清楚宣告 | 每頁建立唯一標題 ID，section 使用 `aria-labelledby`，切頁後統一聚焦標題 |
| `.tr-task-card` 只有 hover 樣式 | 鍵盤使用者看不到目前焦點 | 為卡片及所有自製互動元件加入一致的 `:focus-visible` |
| 基礎字體 13px、步驟文字 11px，次要文字大量使用 `.66–.72` opacity | 亮色、透明背景與低對比主題下難以閱讀 | 基礎字級提升至 14px，資訊文字至少 12px；文字不用低透明度表現層級 |
| 手機 footer 固定單列 | 320px 下返回鍵與長主要按鈕可能溢位 | 480px 開始允許換行，360px 以下改為全寬直向排列 |
| 首頁五張功能卡同層級兩欄排列 | 最後一張落單，聊天與環境操作的心理模型混雜 | 分為「聊天同步」與「酒館環境」兩個語意群組 |

## 無障礙與視覺原則

1. 以 **WCAG 2.2 AA** 為目標；一般文字對比至少 4.5:1，大型文字、圖示與焦點指示至少 3:1。
2. 所有滑鼠可完成的核心操作都必須可用鍵盤完成，且任何時刻都能看見焦點位置。
3. 浮動面板是 modal dialog；嵌入 SillyTavern 側欄的版本是一般內容區塊，不得錯誤宣告成 modal。
4. 換頁、載入與完成狀態要能被讀屏理解，但非同步更新不得任意搶走使用者焦點。
5. 不以顏色、透明度或圖示作為唯一狀態提示，所有狀態都保留可讀文字。
6. 320px 寬度不得產生頁面級水平捲動；互動控制的觸控目標原則上至少 44×44px。

## 任務

### 8-A 浮動 Dialog 語意（P0）

- [x] 僅在 `floating` 模式的面板容器加入 `role="dialog"` 與 `aria-modal="true"`。
- [x] 為浮動面板主標題建立穩定 ID，透過 `aria-labelledby` 關聯 dialog；關閉按鈕提供明確可存取名稱。
- [x] 嵌入模式不得輸出 `role="dialog"` 或 `aria-modal`，維持 SillyTavern 原生 drawer 語意。
- [x] 每個 `[data-screen]` 以 `aria-labelledby` 關聯該頁唯一標題；隱藏頁面持續使用原生 `hidden`，不得進入可存取樹與 Tab 順序。
- [x] 遮罩點擊關閉只作用於真正的 backdrop，不攔截 dialog 內部點擊。

### 8-B 焦點生命週期與鍵盤操作（P0）

- [x] 開啟浮動面板前記錄 `document.activeElement`；開啟後將焦點移到目前頁標題，若無標題則回退至關閉按鈕。
- [x] 為首頁補上可聚焦的語意標題；所有頁面標題使用 `tabindex="-1"`，不增加一般 Tab 停靠點。
- [x] 統一 `showScreen()`：先切換 `hidden`、捲動內容頂端，再於下一個可渲染時機聚焦新頁標題。
- [x] 浮動模式監聽 Escape 並呼叫既有關閉流程；輸入元件或子元件已處理事件時尊重 `defaultPrevented`。
- [x] 實作 Tab／Shift+Tab focus trap，只巡覽目前 dialog 中可見、可用且可聚焦的元素。
- [x] 關閉或 unmount 後移除鍵盤監聽，並把焦點還給原 opener；若 opener 已離開 DOM，使用安全 fallback。
- [x] 面板關閉不取消背景進度；重新開啟後仍可查看既有進度與結果。
- [x] 非同步預覽、進度與診斷結果使用適當的 `aria-live`／`role="status"`，完成時宣告狀態但不搶焦點。

### 8-C 焦點視覺與互動元件（P0）

- [x] 為 `.tr-task-card` 加入高對比 `:focus-visible` 外框，且不得被容器 `overflow` 截斷。
- [x] 統一主要／次要按鈕、雲端聊天列、勾選列、重試按鈕與 `<summary>` 的 `:focus-visible` 樣式。
- [x] hover 與 focus-visible 提供等價資訊，不得只有 hover 才顯示邊框或背景變化。
- [x] 停用控制不進入 Tab 順序；視覺上同時使用透明度與停用游標，但文字仍可辨識。
- [x] 檢查純圖示是否皆有文字或 `aria-label`；裝飾性 Font Awesome 圖示加入 `aria-hidden="true"`。
- [x] 尊重 `prefers-reduced-motion: reduce`，停用非必要動畫與平滑捲動；進度 spinner 仍需有文字狀態。

### 8-D 首頁資訊架構（P1）

- [x] 將「你想做什麼？」下的五張同層級卡片拆成兩個帶標題的語意群組。
- [x] 「聊天同步」包含：上傳目前聊天、更新目前聊天、從雲端建立其他聊天。
- [x] 「酒館環境」包含：備份酒館環境、還原酒館環境；補充涵蓋角色卡、世界書、Persona、Preset 與 Regex。
- [x] 桌面版聊天群組將上傳／更新並排，「從雲端建立其他聊天」作為完整橫列或較低層級入口，避免三張卡再次產生無意義落單。
- [x] 酒館環境維持兩張對稱卡片；兩組使用 `section` 與可見標題，不只靠留白區隔。
- [x] 卡片文案聚焦使用者結果，並保持既有功能路由、Drive disabled 狀態與操作事件不變。
- [x] 640px 以下所有功能卡改為單欄，DOM 閱讀順序與視覺順序一致。

### 8-E 字級、對比與主題相容（P1）

- [x] 面板基礎字級由 13px 提升至 14px，行高由 1.4 提升至至少 1.5。
- [x] 步驟標籤、kicker、技術資訊等 11px 文字提升至至少 12px；主要卡片標題維持至少 14px。
- [x] 盤點所有 `.66–.72` opacity；有語意文字改用主題文字色或至少 `.82`，低透明度只保留於純裝飾元素。
- [x] skipped、disabled 與 not-applicable 狀態仍保留完整文字，不得因整列 opacity 而低於可讀標準。
- [ ] 亮色、暗色、半透明三種背景下檢查文字、邊框、狀態色、callout、focus ring 與 disabled 狀態。
- [x] 狀態色以主題變數與安全 fallback 組合；成功／警告／錯誤除了顏色外保留圖示與文字。
- [x] 支援瀏覽器放大 200% 與系統較大字體，不截斷標題、按鈕或診斷結果。

### 8-F 手機與窄寬度響應式（P1）

- [x] 浮動宿主不得用 inline `overflow: hidden !important` 覆蓋手機捲動規則；固定鎖水平軸並允許 `pan-y`、慣性垂直捲動。
- [x] 在 480px 以下讓 `.tr-step-footer` 支援換行，主要按鈕容器可縮放且按鈕文字可換行。
- [x] 在 360px 以下將「上一步」與主要按鈕改為直向全寬排列，維持 DOM 的返回→主要操作順序。
- [x] footer 與主要操作按鈕最小高度至少 44px，長中文標籤允許兩行且不得被截斷。
- [x] 修正可能造成水平溢位的固定寬度、`max-content`、長檔名、聊天 ID 與技術資訊。
- [ ] 驗證 320、360、390、640px 寬度下 header、功能卡、摘要卡、還原預覽、診斷結果與 footer。
- [ ] 手機虛擬鍵盤開啟時，設定欄位與目前焦點仍能捲動至可見位置。
- [x] 安全區裝置使用 `env(safe-area-inset-*)` 補足浮動面板邊距，不讓底部操作貼住系統手勢區。

### 8-G 自動測試與人工驗收（P2）

- [x] `panelView` 測試浮動模式具備 dialog ARIA、標題關聯，嵌入模式不宣告 modal。
- [x] DOM 行為測試開啟初始焦點、換頁後標題焦點、Escape 關閉、關閉後焦點還原。
- [x] DOM 行為測試 Tab／Shift+Tab 不離開 dialog，hidden／disabled 控制不列入焦點循環。
- [x] 測試所有頁面都具有唯一標題 ID 與正確 `aria-labelledby`。
- [x] 測試首頁輸出「聊天同步」與「酒館環境」兩個群組，五個既有 action／navigation 均保留。
- [x] 加入靜態樣式斷言：task card focus-visible、footer wrap、360px 全寬排列、reduced-motion 規則存在。
- [ ] 視情況導入 axe-core 進行主要畫面的自動無障礙掃描；若不導入，需在文件記錄原因與替代檢查。
- [ ] 以鍵盤及 NVDA 至少完成一次：開啟面板→首頁→上傳確認→返回→設定→關閉。
- [ ] 以亮色／暗色主題及 320px／桌面寬度完成視覺截圖驗收，記錄對比與溢位結果。

### 8-H 文件與規格回寫（P2）

- [ ] 更新開發手冊的面板結構、dialog 行為、首頁分組與響應式規則。
- [ ] 建立鍵盤操作說明：Tab、Shift+Tab、Enter／Space、Escape 與焦點還原。
- [ ] 在 UI 驗收文件記錄 WCAG 2.2 AA 目標、對比門檻、測試主題與測試尺寸。

## 建議實作順序

**8-A → 8-B → 8-C → 8-D → 8-E／8-F → 8-G → 8-H**。

先完成 dialog 與焦點基礎，才能可靠測試後續換頁與響應式 UI；資訊架構調整完成後再統一字級與 breakpoint，可避免重複修改版面。

## 驗收標準

### CI 自動測試

1. 浮動模式具有 `role="dialog"`、`aria-modal="true"` 與有效的 `aria-labelledby`；嵌入模式沒有 modal 宣告。
2. 每個 screen 都有唯一標題與關聯；呼叫 `showScreen()` 後焦點位於該頁標題。
3. Escape 觸發一次關閉；unmount 後不再回應；關閉後焦點回到 opener。
4. Tab／Shift+Tab 在第一與最後可聚焦元素間循環，且不包含 hidden 或 disabled 元素。
5. 首頁兩個群組、五個入口與既有 data-action／data-navigate 完整保留。
6. 主要自製互動元件都有 `:focus-visible`，並包含 reduced-motion 樣式。
7. `npm run verify` 全綠，既有同步、備份、還原及系統檢查測試不得退化。

### 鍵盤與讀屏驗收

8. 不使用滑鼠即可開啟、瀏覽所有頁面、操作表單、返回與關閉。
9. NVDA 能宣告面板名稱、dialog 類型、每次換頁標題、載入中與完成狀態。
10. 焦點始終可見，不進入隱藏畫面或面板背後；關閉後回到原始觸發位置。
11. 背景工作進行時關閉面板不會取消工作，重新開啟仍能查看進度。

### 視覺與響應式驗收

12. 亮色、暗色、半透明主題中的一般文字達 4.5:1，焦點框、圖示與大型文字達 3:1。
13. 瀏覽器放大 200% 後功能不遺失，文字不被截斷，內容可以正常重排。
14. 320px 寬度沒有頁面級水平捲動；footer 按鈕全寬堆疊且文字完整。
15. 360、390、640px 與桌面寬度下，功能群組層級清楚，卡片不產生無意義落單或錯誤閱讀順序。

## 完成定義

- 浮動面板具備完整 dialog 語意、Escape、初始焦點、focus trap 與焦點還原。
- 每次畫面切換都有可預期且可被讀屏感知的焦點／狀態更新。
- 首頁清楚區分聊天同步與酒館環境，五個既有功能沒有遺失或改變行為。
- 文字、狀態與焦點在亮暗主題皆達到目標對比，320px 與 200% 放大不溢位。
- 自動測試全綠，並完成一次鍵盤＋NVDA、亮暗主題與手機尺寸人工驗收。
